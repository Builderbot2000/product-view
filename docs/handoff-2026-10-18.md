## The method: `r12v2`

Code: [round2.py](../trials/prellm/round2.py) (variants in `VARIANTS`), on
[harness.py](../trials/prellm/harness.py) and [stack.py](../trials/prellm/stack.py).

1. **Units:** MiniLM segments re-joined at cosine 0.45, from the 1–3★ stream over a
   4-month window. The vague set-aside runs first, without brand words (round 6, N).
2. **Embedding:** Qwen3-Embedding-0.6B through Ollama on the GPU, with the instruction
   "Identify the specific app feature and the problem with it…". Thresholds are
   quantile-mapped from MiniLM into this space.
3. **Consensus clustering:** 100 Leiden runs over input orders, a co-association graph,
   then Leiden once. The band search aims for **60–85 clusters** (round 8: over-cluster,
   and let the review decide what stays).
4. **Cluster review:** local Qwen3.5 9B, prompt `REVIEW_OWNER3` (specific / broad /
   general, no wording from this app). Two looks: the 12 central members, then 12
   spread across the cluster. A cluster stays only if both say specific.
5. **S, the stand-alone check** (round 12): each kept cluster gets one more call
   (`STANDALONE`, the 12 central members). It asks whether the sentences, each read on
   its own, name the same part of the app; "not" sends the cluster to Miscellaneous.
   It can only remove clusters.
6. **W5:** a cross-fitted logistic regression on the vectors, trained on the cluster
   verdicts, gives each unit its own verdict. Units judged general or broad leave kept
   clusters; outside units judged specific join the nearest kept cluster if they are
   as close as its 10th-percentile member.
7. **C:** symptom units join the cause cluster their own review names (co-occurrence,
   Fisher exact test).

Tried and dropped, each recorded in llm-trials.md: evidence accumulation (round 7);
splitting broad clusters, similarity rescue, context attribution, clause assignment
(round 8); LLM merge of nearby clusters (round 9); all-but-the-top and the stand-alone
test inside the main prompt (round 11); splitting large kept clusters, `split_large`
(round 13).

## How to run

From the repo root, with `.venv/Scripts/python.exe -X utf8`. Ollama must be up, and
Windows reserved the default port at boot, so run it as
`OLLAMA_HOST=127.0.0.1:11600 ollama serve` and set the same `OLLAMA_HOST` for
round2.py. A reboot may free 11434.

```
trials/prellm/round2.py r12v2 R2                       # V1, 5 orders (~4 min)
trials/prellm/round2.py dev5-r12v2 R2                  # dev2..dev6 = development slices
PRELLM_HELDOUT=1 trials/prellm/round2.py final7-r12v2  # V7 held-out, once only
trials/prellm/unit_gold.py sheet v8                    # label sheet for a new slice
```

Results land in `trials/runs/prellm/R2/<mode>-<variant>/` (`R2.json` plus
`labels-R2.npy`, one row per order). To re-score saved labels under a rule, evaluate
them with `harness.evaluate` and the env switches above; no new runs are needed. The
caches are `cache/emb-*.npz` (embeddings) and `cache/llm-calls.db` (model answers).

**Timing (r12v2):** V1, V2, V4, V5 take ~4–6 min; V6 (2,098 units) ~12.5 min; V3 (4,362
units) ~21 min. New review calls add a few minutes. Embedding new texts takes under a
minute on the GPU.
