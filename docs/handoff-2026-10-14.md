## The method (round 5 v2, `R2Options` key `r5v2`)

Code: [trials/prellm/round2.py](../trials/prellm/round2.py), built on
[harness.py](../trials/prellm/harness.py) and [stack.py](../trials/prellm/stack.py).

1. Units: the old cached MiniLM segments re-joined at cosine 0.45, from the 1–3★
   stream over a 4-month window. The old vague set-aside (MiniLM) runs first.
2. **W1:** units are embedded by Qwen3-Embedding-0.6B (CPU, sentence-transformers)
   with the instruction "Identify the specific app feature and the problem with
   it that this sentence from a mobile app review complains about".
3. **U6 + S1:** consensus clustering: 100 Leiden runs over input orders, then a
   co-association graph and Leiden once. The band search aims for 35–50
   clusters.
4. **W2 + W6:** each cluster is reviewed by local Qwen3.5 9B, twice: once on its
   12 members closest to the centre, once on 12 members spread across it. The
   prompt is `REVIEW_OWNER2`: specific / broad / general, pitched at what one
   product team owns. A cluster stays an issue only if both reviews say
   specific. Broad clusters go to Miscellaneous, general clusters to the
   general bucket.
5. **W5:** a logistic regression on the vectors is trained on those cluster
   verdicts (5-fold cross-fitted, the TnT-LLM pattern). It gives each unit its
   own verdict. Units in kept clusters judged general or broad leave. Units
   outside judged specific join the nearest kept cluster if they are at least
   as close as that cluster's 10th-percentile member.

Removed by ablation: the sentiment filter (U4), the range cap (U2), segments
instead of units (W3), outlier reassign (W4), contextual embeddings (S3, clear
fail).

## How to run

From the repo root, with `.venv/Scripts/python.exe -X utf8`:

```
trials/prellm/round2.py r5v2 R2                  # V1, 5 orders (~4 min)
trials/prellm/round2.py r5v2 R2-W5 R2-W6 ...     # drop-one runs
trials/prellm/round2.py dev2-r5v2 R2             # V2 as development data
PRELLM_HELDOUT=1 trials/prellm/round2.py final3-r5v2   # V3 (spent)
```

Results land in `trials/runs/prellm/R2/<variant>/` (JSON per run, plus labels
`.npy`). Embeddings are cached by text in `trials/runs/prellm/cache/emb-*.npz`.
Cluster-review answers are cached in `trials/runs/prellm/cache/llm-calls.db`.
New variants go in `VARIANTS` in round2.py.

**Timing:** CPU embedding is ~0.4 s per unit. V1/V2 windows are ~700 units; V3
was 4,362 units (36 min to embed, then ~5 min per order), which breaks the
45-minute trial budget. Before the next large-window run, move embedding to
the GPU (e.g. Ollama `qwen3-embedding`, or a CUDA torch build: the venv has
`torch 2.14.0+cpu`).

  examples ("technical difficulties", "something went wrong") came from this
  app's reviews. Make them neutral and re-check on V1 (~10 min).
- The legacy vague set-aside (`trials/prellm/legacy/vague.py`, inherited from
  production) has "rbc", "royal", "canada" in its word lists.
- V3 was labelled by the same agent that built the method. A team member's key
  would be the independent check.
